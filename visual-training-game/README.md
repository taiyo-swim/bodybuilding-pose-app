# 視覚トレーニングゲーム（visual_training_game）

一瞬だけ表示されるガボールパッチの傾きを、リズムに乗せて判別し続けるゲーム。

**仕様と判断基準は [`CLAUDE.md`](./CLAUDE.md) が正。** 迷ったらまずそちらを読むこと。
実装が先行して仕様が後追いにならないよう、決定事項は会話ではなく `CLAUDE.md` に書く。

---

## セットアップ

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # drift の生成コード
flutter test
tool/compile_shaders.sh                                     # シェーダーのコンパイル検証
flutter run                                                 # 実機推奨
```

`*.g.dart` は `.gitignore` 済み。クローン直後は必ず `build_runner` を回すこと。

## 開発メニュー（Phase 1）

アプリを起動すると開発メニューが出る。仕様書 9 のホーム画面ではない。Phase 2 で置き換える。

| 項目 | 何を見るか |
|---|---|
| プレイ（3分） | コアループ。試行ログを DB に残す |
| プレイ（30秒・記録なし） | 動作確認用 |
| ディザリング確認 | コントラスト 1〜5% が段々にならないか（仕様書 3.2） |
| 音ズレ計測 | ビートと音のずれ（仕様書 11-6） |

### 音ズレの測り方

アプリ内で自動的に測れるのは**ソフトウェア側の遅れだけ**で、
端末のオーディオ出力バッファぶんの遅れは測れない。実際の音響遅延はこう出す。

1. 「音ズレ計測」を開く。拍頭で白い円が光る
2. **別の端末**でこの画面を録画する（60fps 以上が望ましい）
3. 録画の波形で「クリック音の立ち上がり」と「円が光るフレーム」の差を読む
4. その差が音響的な遅延。`Metronome` を先に鳴らして打ち消す

画面に出ている統計は、その測定の前提になるばらつきの確認用。
ばらつき（SD）が大きい端末では、そもそも音をペースメーカーとして使えない。

## 実機で確認しないと「完了」にならない項目

モデルは画面を見られない。以下は**実機で目視・数値確認し、結果をコミットメッセージに残す**こと（仕様書 12）。

- [ ] **ディザリング**（仕様書 3.2）— コントラスト 2〜5% が段々にならず滑らかに見えること
- [ ] **タイミング**（仕様書 3.3）— 試行ログの `ms_actual` が目標値の ±1フレーム以内
- [ ] **音ズレ**（仕様書 11-6）— ビートと音の提示ずれを実測
- [ ] **フリック閾値**（仕様書 4.1）— 初期値 24論理px が親指1本で妥当か

### Phase 1 の完了条件（仕様書 11）

実機で 60ms・3%コントラストの条件が正しく提示され、試行ログの `ms_actual` が
目標値の ±1フレーム以内に収まっていること。

## 着手していない領域と、その理由

仕様書セクション0の未決事項に触れるため、**推測で埋めずに止めている**。

| 項目 | 状態 |
|---|---|
| B: 閾値推定の方法と試行数 | 週次コンディション測定モードは未着手。`session.thresholdContrast` は null のまま |
| C: 初回キャリブレーション手順 | オンボーディング未着手。視距離は暫定40cm固定で動く |
| D: 計測イベント（行動ログ） | 未着手。訓練ログ（`trial`）とは別物 |
| E: アカウント引き継ぎ | 未着手。Firebase は Phase 2 |
| F: リーグ人数・曲数・課金 | 未着手。Phase 3 |

未決事項A（刺激の物理サイズ）は暫定方針「ppi補正のみ・視距離40cm固定」で実装済み。
λ の一次表現は**視角（分）**であり、論理px への換算は `ViewingGeometry` 1箇所に閉じている。

## 表現の制約（仕様書 10）

アプリ名・説明文・スクリーンショット・アプリ内文言のいずれにも
**「視力回復」「視力が上がる」を入れない。** 非医療機器において明確にNGとされる表現。
